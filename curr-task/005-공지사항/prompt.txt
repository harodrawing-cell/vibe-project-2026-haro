# 007. HARO NOTICE — 게시글 수정 페이지 추가

## 1. 작업 목표

기존 NOTICE 게시글 상세 화면에 `수정` 버튼을 추가하고, 클릭하면 해당 게시글의 수정 페이지가 열리도록 구현한다.

첨부한 `HARO_NOTICE_Edit_Demo.html`의 디자인과 입력 구성을 참고하되, 기존 프로젝트의 HEADER, FOOTER 및 공통 CSS를 재사용한다.

## 2. 글 수정 화면

- 기존 글쓰기 페이지와 동일한 디자인을 적용한다.
- 페이지 제목은 `NOTICE`, 화면 안내는 `공지사항 수정`으로 표시한다.
- 기존 게시글의 카테고리, 제목, 작성자, 본문 및 첨부 이미지를 불러온다.
- 제목과 본문은 편집 가능하게 하고 작성자는 읽기 전용으로 표시한다.
- 기존 이미지 확인, 이미지 변경 및 삭제 기능을 준비한다.
- 하단에 `취소`와 `수정 완료` 버튼을 배치한다.

## 3. 수정 기능

- 게시글 ID를 기준으로 기존 데이터를 불러온다.
- 제목과 본문은 필수 항목으로 검증한다.
- `수정 완료` 클릭 시 기존 게시글을 업데이트한다.
- 새 게시글을 생성하거나 기존 게시글 ID를 변경하지 않는다.
- 수정 성공 후 해당 게시글 상세 페이지로 이동한다.
- 취소 시 변경사항이 있으면 확인 메시지를 표시한다.
- 수정에 실패하면 오류를 안내하고 입력 내용을 유지한다.
- 수정할 글이 없으면 안내 후 NOTICE 목록으로 돌아갈 수 있도록 한다.

## 4. 접근 권한 및 데이터 저장

- 게시글 수정은 관리자에게만 허용한다.
- 수정 버튼 역시 관리자에게만 표시한다.
- 관리자 권한은 화면 표시뿐 아니라 실제 데이터 저장 단계에서도 검증한다.
- 현재 백엔드가 없다면 테스트 모드로 구현하되 실제 서버 저장과 구분한다.
- 추후 데이터베이스를 연결할 수 있도록 데이터 처리 로직을 분리한다.

## 5. 반응형

Desktop First 방식으로 구현한다.

- 데스크탑: 중앙 최대 너비 약 900px
- 태블릿: 화면 너비에 맞게 입력 영역과 여백 축소
- 모바일: 입력 항목 세로 배치 및 버튼 터치 영역 확보

1920px, 1024px, 768px, 390px에서 확인한다.

## 6. 기존 기능 유지

- NOTICE 목록, 검색, 페이지네이션 유지
- 기존 게시글 상세 보기 유지
- 기존 글쓰기 기능 유지
- HEADER 및 FOOTER 디자인 유지
- 다른 홈페이지 섹션은 수정하지 않음
- 프로젝트 내 기존 라우팅과 데이터 구조를 우선 재사용

작업 완료 후 `task-history/task.md`에 변경 내용을 기록하고 기존 `prompt.txt`는 수정하지 않는다.

**최종 목표:** NOTICE 게시글 상세 화면에서 수정 버튼을 누르면 기존 내용이 입력된 수정 페이지가 열리고, 수정한 내용을 저장하면 같은 게시글의 상세 화면에서 변경사항을 확인할 수 있도록 구현한다.
