
# 004. STORY 섹션 — Instagram API 자동 연동 구현

**타겟 사이트:** https://www.mandaco.co.kr/  
**Instagram:** https://www.instagram.com/liberoflowerpig/  
**작업 대상:** STORY 섹션  
**참조 이미지:** 데스크탑 → 태블릿 → 모바일 순서

## 1. 작업 목표

첨부된 3장의 화면을 기준으로 STORY 섹션을 구현한다.

기존 4개의 컬러 박스를 Instagram API에서 가져온 실제 인스타툰 이미지로 교체하고, 4개를 랜덤으로 표시한다.

각 이미지를 클릭하면 해당 Instagram 게시물로 직접 이동하도록 구현한다.

현재 API 인증 정보가 준비되지 않았으므로, **프론트엔드와 API 연동 구조를 우선 완성하고 인증 정보 등록 후 실데이터로 전환할 수 있도록 개발한다.**

## 2. STORY 화면 구성

- 기존 STORY 제목, 구분선, 소개 문구 및 Instagram 버튼을 유지한다.
- 데스크탑은 좌측 텍스트와 우측 2×2 이미지 그리드로 구성한다.
- 태블릿은 가로형 구성을 유지하면서 크기와 간격을 조정한다.
- 모바일은 세로형으로 변경하고 이미지 2×2 그리드를 하단에 배치한다.
- 이미지 사이에 일정한 간격을 적용한다.
- 이미지와 전체 컨테이너에 기존의 둥근 모서리 디자인을 유지한다.
- 기존 다른 섹션의 CSS 및 JavaScript에 영향을 주지 않는다.

## 3. Instagram 버튼

- Instagram 버튼은 공식 프로필로 이동한다.
- 주소: https://www.instagram.com/liberoflowerpig/
- 새 탭에서 열리도록 한다.

## 4. Instagram API 연동

Meta 공식 Instagram API with Instagram Login 방식을 사용한다.

- 크리에이터/비즈니스 계정 연동을 전제로 한다.
- 게시물 ID, 미디어 유형, 이미지 URL, 썸네일 URL, 게시물 permalink 등 필요한 데이터를 가져온다.
- 이미지 게시물과 캐러셀 게시물의 대표 이미지를 지원한다.
- 영상 게시물을 표시할 경우 제공되는 썸네일을 사용한다.
- 각 이미지와 실제 게시물 permalink를 연결한다.
- 인스타툰 게시물만 표시할 수 있도록 해시태그 또는 별도 게시물 ID 목록 기반의 필터링 구조를 제공한다.

API 호출은 서버 측에서 처리하며 브라우저에서 인증 토큰에 직접 접근하지 않도록 한다.

## 5. 랜덤 이미지 표시

- API에서 가져온 인스타툰 게시물 중 4개를 랜덤 선택한다.
- 중복 없이 4개를 표시한다.
- 페이지를 새로 열거나 새로고침하면 다시 랜덤 선택한다.
- 반응형 화면 크기 변경만으로 이미지를 다시 선택하지 않는다.
- 이미지 로딩 중 레이아웃이 흔들리지 않도록 한다.
- 게시물 링크는 반드시 해당 이미지의 실제 permalink를 사용한다.
- 이미지가 4개 미만인 경우 존재하는 이미지 수만큼만 표시한다.

## 6. API 데이터 업데이트

- 새 인스타툰 게시물이 등록되면 다음 데이터 갱신 시 반영될 수 있도록 한다.
- 서버 측 데이터 캐싱을 적용하여 불필요한 API 호출을 줄인다.
- 기존 게시물과 신규 게시물을 함께 랜덤 선택 대상으로 관리한다.
- 인증 만료, API 호출 오류, 이미지 로딩 실패에 대응한다.
- 필요하면 마지막으로 정상 수집한 데이터를 안전하게 보관하는 구조를 적용한다.

## 7. API 연결 전 임시 구현

현재 Meta API 인증 정보가 없는 상태이므로 다음 기능을 먼저 완성한다.

1. 기존 STORY 섹션 레이아웃 유지 및 수정.
2. 2×2 이미지 그리드와 이미지 간격 구현.
3. 랜덤 4개 선택 JavaScript 작성.
4. 이미지 데이터와 게시물 URL을 연결하는 구조 구현.
5. API 응답 형식에 맞는 데이터 변환 모듈 작성.
6. 테스트용 데이터 모드 및 API 연결 모드 분리.
7. 실제 이미지가 없는 경우 기존 컬러 박스를 임시 플레이스홀더로 표시.
8. Instagram 프로필 버튼은 즉시 실제 연결.
9. API 미연결 상태를 개발 환경에서 명확히 표시.

실제 API 호출이 성공하기 전에는 자동 연동이 완료된 것으로 표시하지 않는다.

## 8. 보안 및 배포 구조

- Instagram Access Token 및 App Secret을 HTML, CSS, 프론트엔드 JavaScript에 저장하지 않는다.
- 서버리스 API를 별도로 구성할 수 있도록 모듈을 분리한다.
- 현재 프로젝트의 호스팅 환경을 확인하고 적절한 서버 측 실행 방식을 선택한다.
- GitHub Pages 사용 시 서버리스 API를 외부에 구성하거나 안전한 예약 갱신 방식으로 공개 데이터만 배포한다.
- API 키나 인증 정보가 없는 경우 임의의 값을 생성하지 않는다.
- 추후 환경변수 설정만으로 실제 API 연동을 활성화할 수 있도록 준비한다.

## 9. 반응형 기준

Desktop First 방식.

- 데스크탑: 1025px 이상 (1920px 디자인 기준)
- 태블릿: `@media (max-width: 1024px)`
- 모바일: `@media (max-width: 768px)`

첨부된 기기별 참조 이미지의 요소 배치, 크기, 간격, 정렬을 분석하여 구현한다.

## 10. 작업 및 검증

- 기존 HTML/CSS/JavaScript 구조를 최대한 보존한다.
- 프론트엔드 랜덤 표시 기능을 우선 구현한다.
- 실제 API 인증이 필요한 미완료 항목을 구분해 기록한다.
- API 연동과 무관한 다른 섹션은 수정하지 않는다.
- 1920px, 1024px, 768px, 390px 화면에서 레이아웃을 검증한다.
- 작업 내용과 미완료 API 설정 항목을 `task-history/task.md`에 기록한다.
- 초기 구현 요구사항인 `prompt.txt`는 임의로 덮어쓰지 않는다.
