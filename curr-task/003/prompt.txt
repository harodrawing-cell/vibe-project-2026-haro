# [작업 요청] STORY 섹션 반응형 웹 구현

# 004. STORY 섹션 디자인 리뉴얼 및 반응형 

**타겟 사이트:** https://www.mandaco.co.kr/  
**작업 대상:** 기존 STORY 섹션  
**디자인 기준:** 새로 첨부한 STORY 디자인 시안

## 1. 작업 목표

첨부한 디자인 시안을 기준으로 기존 STORY 섹션을 새롭게 디자인한다.

- 기존의 단조로운 회색 배경과 불규칙한 이미지 배치를 개선한다.
- 따뜻한 크림톤 배경, 둥근 카드, 부드러운 그림자를 적용한다.
- 이미지 시안의 레이아웃, 비율, 정렬, 여백, 타이포그래피를 최대한 재현한다.
- 기존 로컬 이미지 랜덤 표시 기능과 Instagram 연결 기능은 유지한다.
- STORY 외 다른 섹션은 수정하지 않는다.

## 2. 데스크탑 레이아웃

- STORY 콘텐츠를 중앙 정렬된 큰 라운드 컨테이너 안에 배치한다.
- 컨테이너 배경은 따뜻한 크림톤으로 적용한다.
- 왼쪽은 텍스트 및 캐릭터 영역, 오른쪽은 이미지 그리드로 구성한다.
- 좌측 상단에 핑크 컬러 `STORY` 타이틀과 가로 구분선을 배치한다.
- 메인 카피는 다음과 같이 2줄로 구성한다.

  오늘도 적당히 덤덤한  
  현생 고양이 하로

- 메인 카피 아래에 설명 문구와 Instagram 버튼을 배치한다.
- 좌측 하단에는 누워 있는 하로 캐릭터를 장식 이미지로 배치한다.
- 오른쪽에는 동일한 크기의 인스타툰 이미지 카드 4개를 2열×2행으로 정렬한다.
- 이미지 카드 사이에 일정한 간격을 적용한다.

## 3. 스타일 디자인

- 전체 배경: 따뜻한 아이보리·크림 계열
- 컨테이너: 큰 라운드 모서리
- 카드: 화이트 또는 연한 크림 배경
- 카드 모서리: 약 18~24px
- 카드 간격: 약 16~20px
- 카드 그림자: 부드럽고 약한 그림자
- 제목: 짙은 브라운 또는 기존 브랜드 컬러
- Instagram 버튼: 핑크·오렌지·퍼플 계열 그라데이션
- 버튼과 카드에 자연스러운 Hover 인터랙션 적용

색상과 크기는 고정값보다 첨부 디자인 시안의 실제 비율을 우선한다.

## 4. 인스타툰 랜덤 이미지 기능

- 기존 `images/story/` 폴더의 로컬 이미지를 사용한다.
- 기존 `data/story.json`의 이미지 경로와 게시물 URL을 재사용한다.
- 페이지 로딩 시 4개의 이미지를 중복 없이 랜덤 선택한다.
- 새로고침 시 랜덤 이미지 조합을 변경한다.
- 화면 크기 변경 시에는 이미지를 다시 선택하지 않는다.
- 4개의 이미지 카드는 동일한 정사각형 비율로 표시한다.
- 이미지 원본 비율을 유지하면서 중요한 캐릭터와 텍스트가 잘리지 않도록 한다.
- `object-fit: contain`을 기본으로 하고 카드 안의 여백과 배경색을 통일한다.

## 5. Instagram 링크 및 인터랙션

- Instagram 버튼은 기존 프로필로 연결한다.
- URL: https://www.instagram.com/liberoflowerpig/
- 랜덤 이미지 카드를 클릭하면 해당 이미지와 연결된 실제 인스타그램 게시물로 이동한다.
- 외부 링크는 새 탭에서 연다.
- 마우스 Hover 시 카드가 약 1.03배 확대되고 그림자가 부드럽게 강조되도록 한다.
- 모바일에서는 이미지 터치로 게시물에 이동한다.
- 게시물 URL이 등록되지 않은 이미지는 클릭 기능을 적용하지 않는다.
- Instagram API 연결 기능은 사용하지 않는다.

## 6. 반응형 디자인

Desktop First 방식으로 구현한다.

**데스크탑: 1025px 이상 (1920px 디자인 기준)**
- 좌측 텍스트·캐릭터 / 우측 2×2 이미지 그리드.
- 이미지 시안과 동일한 가로형 레이아웃 유지.

**태블릿: 1024px 이하**
- 데스크탑의 가로형 구조 유지.
- 컨테이너, 텍스트, 캐릭터 및 이미지 카드 크기를 화면에 맞게 축소한다.
- 콘텐츠 간 간격과 여백을 조정한다.

**모바일: 768px 이하**
- 세로형 레이아웃으로 전환한다.
- STORY 타이틀 → 메인 카피 → 설명 문구 → Instagram 버튼 → 이미지 그리드 순서로 배치한다.
- 텍스트와 버튼은 중앙 정렬한다.
- 하단의 이미지 그리드는 2열×2행을 유지한다.
- 모바일에서는 장식용 하로 캐릭터를 숨기거나 화면에 맞게 축소한다.
- 카드 크기, 여백, 간격을 조정해 가로 스크롤이 발생하지 않도록 한다.

## 7. 구현 시 주의사항

- 기존 STORY 섹션의 HTML/CSS/JavaScript 구조를 최대한 재사용한다.
- 기존 데이터와 랜덤 이미지 로딩 기능을 유지한다.
- 첨부 시안의 하로 캐릭터는 디자인 참고용이며, 실제 웹사이트에서는 프로젝트에 있는 원본 하로 캐릭터 이미지만 사용한다.
- 원본 캐릭터 이미지가 없다면 임의의 캐릭터를 생성하지 말고 장식 영역을 생략한다.
- 이미지 시안에 있는 설명용 아이콘, 디자인 포인트 안내 문구, 데스크탑·태블릿·모바일 라벨은 웹사이트에 구현하지 않는다.
- 다른 섹션의 디자인, 고정 헤더, 스크롤 동작은 수정하지 않는다.
- 기존 프로젝트의 CSS 네이밍 규칙과 Spec-kit 지침을 따른다.

## 8. 검증 및 기록

- 1920px, 1024px, 768px, 390px 화면에서 디자인을 확인한다.
- 이미지 카드 크기, 여백, 텍스트 줄바꿈, 캐릭터 배치를 검증한다.
- 랜덤 이미지 표시와 각 게시물 클릭 이동 기능을 확인한다.
- 이미지가 누락되거나 깨지지 않도록 검증한다.
- 변경 내용을 `task-history/task.md`에 기록한다.
- 기존 `prompt.txt`는 수정하지 않는다.

**최종 목표:** 첨부한 새 디자인 시안과 유사한 따뜻하고 감성적인 STORY 섹션을 구현하면서 기존 랜덤 이미지 및 Instagram 링크 기능을 정상 유지한다.























































                    # 004. STORY 섹션 — Instagram API 자동 연동 구현

                    **타겟 사이트:** https://www.mandaco.co.kr/  
                    **Instagram:** https://www.instagram.com/liberoflowerpig/  
                    **작업 대상:** STORY 섹션  
                    **참조 이미지:** 데스크탑 → 태블릿 → 모바일 순서

                    ## 1. 작업 목표

                    첨부된 3장의 화면을 기준으로 STORY 섹션을 구현한다.

                    기존 4개의 컬러 박스를 Instagram API에서 가져온 실제 인스타툰 이미지로 교체하고, 4개를 랜덤으로 표시한다.

                    각 이미지를 클릭하면 해당 Instagram 게시물로 직접 이동하도록 구현한다.

                    현재 API 인증 정보가 준비되지 않았으므로, **프론트엔드와 API 연동 구조를 우선 완성하고 인증 정보 등록 후 실데이터로 전환할 수 있도록 개발한다.**

                    ## 2. STORY 화면 구성

                    - 기존 STORY 제목, 구분선, 소개 문구 및 Instagram 버튼을 유지한다.
                    - 데스크탑은 좌측 텍스트와 우측 2×2 이미지 그리드로 구성한다.
                    - 태블릿은 가로형 구성을 유지하면서 크기와 간격을 조정한다.
                    - 모바일은 세로형으로 변경하고 이미지 2×2 그리드를 하단에 배치한다.
                    - 이미지 사이에 일정한 간격을 적용한다.
                    - 이미지와 전체 컨테이너에 기존의 둥근 모서리 디자인을 유지한다.
                    - 기존 다른 섹션의 CSS 및 JavaScript에 영향을 주지 않는다.

                    ## 3. Instagram 버튼

                    - Instagram 버튼은 공식 프로필로 이동한다.
                    - 주소: https://www.instagram.com/liberoflowerpig/
                    - 새 탭에서 열리도록 한다.

                    ## 4. Instagram API 연동

                    Meta 공식 Instagram API with Instagram Login 방식을 사용한다.

                    - 크리에이터/비즈니스 계정 연동을 전제로 한다.
                    - 게시물 ID, 미디어 유형, 이미지 URL, 썸네일 URL, 게시물 permalink 등 필요한 데이터를 가져온다.
                    - 이미지 게시물과 캐러셀 게시물의 대표 이미지를 지원한다.
                    - 영상 게시물을 표시할 경우 제공되는 썸네일을 사용한다.
                    - 각 이미지와 실제 게시물 permalink를 연결한다.
                    - 인스타툰 게시물만 표시할 수 있도록 해시태그 또는 별도 게시물 ID 목록 기반의 필터링 구조를 제공한다.

                    API 호출은 서버 측에서 처리하며 브라우저에서 인증 토큰에 직접 접근하지 않도록 한다.

                    ## 5. 랜덤 이미지 표시

                    - API에서 가져온 인스타툰 게시물 중 4개를 랜덤 선택한다.
                    - 중복 없이 4개를 표시한다.
                    - 페이지를 새로 열거나 새로고침하면 다시 랜덤 선택한다.
                    - 반응형 화면 크기 변경만으로 이미지를 다시 선택하지 않는다.
                    - 이미지 로딩 중 레이아웃이 흔들리지 않도록 한다.
                    - 게시물 링크는 반드시 해당 이미지의 실제 permalink를 사용한다.
                    - 이미지가 4개 미만인 경우 존재하는 이미지 수만큼만 표시한다.

                    ## 6. API 데이터 업데이트

                    - 새 인스타툰 게시물이 등록되면 다음 데이터 갱신 시 반영될 수 있도록 한다.
                    - 서버 측 데이터 캐싱을 적용하여 불필요한 API 호출을 줄인다.
                    - 기존 게시물과 신규 게시물을 함께 랜덤 선택 대상으로 관리한다.
                    - 인증 만료, API 호출 오류, 이미지 로딩 실패에 대응한다.
                    - 필요하면 마지막으로 정상 수집한 데이터를 안전하게 보관하는 구조를 적용한다.

                    ## 7. API 연결 전 임시 구현

                    현재 Meta API 인증 정보가 없는 상태이므로 다음 기능을 먼저 완성한다.

                    1. 기존 STORY 섹션 레이아웃 유지 및 수정.
                    2. 2×2 이미지 그리드와 이미지 간격 구현.
                    3. 랜덤 4개 선택 JavaScript 작성.
                    4. 이미지 데이터와 게시물 URL을 연결하는 구조 구현.
                    5. API 응답 형식에 맞는 데이터 변환 모듈 작성.
                    6. 테스트용 데이터 모드 및 API 연결 모드 분리.
                    7. 실제 이미지가 없는 경우 기존 컬러 박스를 임시 플레이스홀더로 표시.
                    8. Instagram 프로필 버튼은 즉시 실제 연결.
                    9. API 미연결 상태를 개발 환경에서 명확히 표시.

                    실제 API 호출이 성공하기 전에는 자동 연동이 완료된 것으로 표시하지 않는다.

                    ## 8. 보안 및 배포 구조

                    - Instagram Access Token 및 App Secret을 HTML, CSS, 프론트엔드 JavaScript에 저장하지 않는다.
                    - 서버리스 API를 별도로 구성할 수 있도록 모듈을 분리한다.
                    - 현재 프로젝트의 호스팅 환경을 확인하고 적절한 서버 측 실행 방식을 선택한다.
                    - GitHub Pages 사용 시 서버리스 API를 외부에 구성하거나 안전한 예약 갱신 방식으로 공개 데이터만 배포한다.
                    - API 키나 인증 정보가 없는 경우 임의의 값을 생성하지 않는다.
                    - 추후 환경변수 설정만으로 실제 API 연동을 활성화할 수 있도록 준비한다.

                    ## 9. 반응형 기준

                    Desktop First 방식.

                    - 데스크탑: 1025px 이상 (1920px 디자인 기준)
                    - 태블릿: `@media (max-width: 1024px)`
                    - 모바일: `@media (max-width: 768px)`

                    첨부된 기기별 참조 이미지의 요소 배치, 크기, 간격, 정렬을 분석하여 구현한다.

                    ## 10. 작업 및 검증

                    - 기존 HTML/CSS/JavaScript 구조를 최대한 보존한다.
                    - 프론트엔드 랜덤 표시 기능을 우선 구현한다.
                    - 실제 API 인증이 필요한 미완료 항목을 구분해 기록한다.
                    - API 연동과 무관한 다른 섹션은 수정하지 않는다.
                    - 1920px, 1024px, 768px, 390px 화면에서 레이아웃을 검증한다.
                    - 작업 내용과 미완료 API 설정 항목을 `task-history/task.md`에 기록한다.
                    - 초기 구현 요구사항인 `prompt.txt`는 임의로 덮어쓰지 않는다.
