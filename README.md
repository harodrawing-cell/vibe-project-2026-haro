# HARO 웹사이트 프로젝트

하로 캐릭터와 콘텐츠를 소개하는 단일 페이지 웹사이트 프로젝트입니다. 기본 스택은 HTML5, CSS3, Vanilla JavaScript이며, 현재 저장소의 실제 파일과 승인된 PRD를 기준으로 작업합니다.

## 로컬 미리보기

Node.js가 설치된 환경에서 `preview.cmd`를 실행하거나 프로젝트 폴더에서 `node scripts/preview.cjs`를 실행합니다. 서버 실행 창을 유지한 채 브라우저에서 http://127.0.0.1:8080/ 에 접속합니다. 종료하려면 서버 창에서 Ctrl+C를 누릅니다.

STORY 이미지는 JSON을 불러오므로 `index.html` 파일을 직접 열지 않고 위 HTTP 주소를 사용합니다. 수정 후 브라우저를 새로고침하면 반영됩니다.

GOODS 카드 8개는 로컬 상품 상세(`pages/goods/goods-detail.html?id=상품ID`)로 연결됩니다. 장바구니는 `pages/cart/cart.html`이며 모든 페이지 상단 아이콘에서 열 수 있습니다. 상품은 `data/products.json`, 장바구니는 localStorage `haro-cart-v1`로 관리합니다. 무지노트는 첨부 화면에서 확인한 4,500원을 사용하고, 가격이 확인되지 않은 7개 상품은 ‘가격 미등록’으로 표시해 담기를 막습니다. 실제 결제·주문·배송은 제공하지 않습니다. [상품/장바구니 안내](./document/GOODS_CART.md)를 참고하세요.

NOTICE 게시판은 홈페이지의 NOTICE 메뉴 또는 `http://127.0.0.1:8080/pages/notice/notice-list.html`에서 확인합니다. Firebase 프로젝트 `haro-web-project`의 Firestore `(default)` DB, `notices` 컬렉션을 사용합니다. 로그인 화면은 `pages/notice/login.html`이며 하단 회원가입 링크를 통해 `pages/notice/signup.html`로 이동합니다. 회원가입 페이지에는 이름·아이디·비밀번호·이메일 폼과 로그인 복귀 링크가 있습니다. 상단에 로그인 버튼을 표시하고 로그인 후 환영 문구 옆에 로그아웃 버튼을 표시하며, 로그인한 모든 회원은 공지를 작성할 수 있고 수정·삭제는 작성자 본인과 관리자만 이용하도록 연결했습니다. **Spark 무료 요금제로 동작하도록 변경했습니다. 실제 사용 전 이메일/비밀번호 인증 활성화, Firestore 보안 규칙 게시와 관리자 수동 등록이 필요합니다. Cloud Functions/Blaze는 사용하지 않습니다.** [계정 설정 안내](./document/NOTICE_Firebase.md)를 참고하세요. 첨부 이미지는 기존 WebP/Base64 방식을 유지합니다.

공지사항 HTML 5개는 `pages/notice/`에 있습니다. 같은 폴더의 목록·상세·작성·수정 링크는 유지하며, 공통 CSS·JavaScript·이미지 및 홈페이지는 `../../` 경로로 참조합니다. 기존 localStorage 원본은 보존하지만 Firebase로 자동 업로드하지 않습니다. 조회 실패 시 로컬 데이터로 대체하지 않습니다.

Q&A(묻고 답하기)는 `pages/notice/qna.html`에서 확인합니다. 기존 로그인과 NOTICE 디자인을 재사용하며, 질문 유형 5개·공개 제목 검색·7개 단위 목록·공개/비공개 질문·관리자 답변을 지원합니다. 질문 수정·삭제는 작성자 본인만 가능하고 관리자는 답변을 관리합니다. 비공개 질문의 실제 제목·본문·답변은 공개 목록 데이터와 분리했습니다. 실제 사용 전 최신 Firestore 규칙을 게시해야 합니다. [Q&A 구조와 적용·검증 안내](./document/QNA.md)를 참고하세요.

공지사항과 계정/Firebase 관련 JavaScript는 `js/services/`에 모아 관리합니다. 공통 도구(`notice-common.js`) → Firebase 연결(`notice-firebase.js`) → 계정 서비스(`account-service.js`) → 권한(`notice-auth.js`) → 필요한 화면 코드 순서로 불러옵니다. 인증은 웹 SDK에서 직접 처리하며 실제 이메일은 회원 정보로 저장합니다. 아이디 기반 내부 인증 주소를 사용하므로 이메일 인증·비밀번호 재설정 메일은 제공하지 않습니다. `api/`의 이전 함수 코드는 현재 사용하지 않습니다. 쇼핑·장바구니·STORY 등 다른 JavaScript는 기존 `js/` 경로를 유지합니다.

메인 index.html의 HEADER 위에만 같은 게시판 저장소의 최신 글을 최대 3개까지 표시하는 고정 공지 배너가 있습니다. 4초마다 순환하며 제목을 누르면 해당 상세 페이지로 이동합니다. 1개일 때는 자동 전환하지 않고, 글이 없거나 데이터를 읽지 못하면 숨깁니다. 일시정지/재생을 지원하며 모션 감소 설정에서는 자동 전환을 시작하지 않습니다. NOTICE 라벨은 목록으로, 게시글 제목은 해당 상세 페이지로 이동합니다. 닫으면 배너 여백이 제거되며 새로고침하거나 index에 다시 접속하면 다시 표시됩니다. 게시글 데이터 복사본이나 배너용 샘플 글을 만들지 않습니다. 현재 저장소에는 고정 공지 필드가 없어 기존 기본 정렬(최신 작성일)을 그대로 사용합니다.

이전 로컬 버전은 카테고리별 `[샘플]` 게시글 3개씩을 생성했습니다. Firebase 버전은 방문 시 샘플이나 기본 글을 생성하지 않습니다. 기존 글과 샘플의 이전은 범위 확정 후 별도로 진행합니다.

로컬 미리보기 서버는 기존 `/notice*.html` 및 중간 경로 `/pages/notice*.html`을 `/pages/notice/notice*.html`로 308 리다이렉트하며 게시글 ID·검색어 등 쿼리를 유지합니다. `notice.html?view=detail&id=...`도 새 폴더의 호환 페이지를 통해 상세 화면으로 연결됩니다. 일반 정적 호스팅에는 이 Node 서버 규칙이 적용되지 않으므로, 배포 서버에서도 아래 5개 매핑과 `/pages/` 중간 경로에 동일한 쿼리 보존 리다이렉트를 설정해야 합니다. 별도 규칙이 없는 GitHub Pages 등에서는 기존 URL이 404가 될 수 있습니다. 루트에 HTML 리다이렉트 파일을 남기면 `index.html`만 유지하는 목표와 충돌하므로 추가하지 않았습니다.

| 기존 URL | 새 URL |
|---|---|
| `/notice.html` | `/pages/notice/notice.html` |
| `/notice-list.html` | `/pages/notice/notice-list.html` |
| `/notice-detail.html` | `/pages/notice/notice-detail.html` |
| `/notice-edit.html` | `/pages/notice/notice-edit.html` |
| `/notice-write.html` | `/pages/notice/notice-write.html` |

## 작업 시작 전 필독

README를 읽고 작업을 시작할 때는 **가장 먼저 [`task-history/task.md`](./task-history/task.md)도 이어서 읽으세요.** 이 파일에는 이전 작업과 미완료 사항이 기록되어 있으므로, 현재 저장소 상태와 대조해 중복 작업을 방지합니다.

1. `task-history/task.md`의 이전 작업, 미완료 사항, 검증 상태를 확인합니다. 현재 요청과 실제 저장소 상태에 맞춰 오래된 인계 내용은 검증·갱신합니다.
2. 이번 요청의 목표, 수정 범위, 보존할 기능과 검증 기준을 확인합니다.
3. [`spec-kit/HARO_SpecKit.md`](./spec-kit/HARO_SpecKit.md)를 프로젝트 공통 규약으로 읽고 적용합니다.
4. [`spec-kit/AGENTS.md`](./spec-kit/AGENTS.md)의 공통 규칙과 현재 작업에 해당하는 부분을 확인합니다.
5. [`document/`](./document/)의 PRD·요약·에이전트 지침 중 현재 작업과 관련된 문서를 확인합니다. 없는 문서나 자산은 추측하지 않습니다.
6. 실제 HTML, 연결된 CSS, 이미지·폰트 경로와 기존 반응형·상호작용 구조를 조사한 뒤 요청 범위만 수정합니다.

작업을 마치면 `task-history/task.md`에 완료한 내용, 수정 파일, 실제 검증 결과, 미완료·미검증 항목을 갱신해 다음 작업이 중복 없이 이어지도록 합니다.

규약이나 필수 자료를 찾을 수 없으면 누락 사항을 밝히고 확인 가능한 범위만 진행합니다. 확인하지 않은 동작이나 검증을 완료한 것처럼 보고하지 않습니다.

## 문서 적용 범위와 우선순위

규칙이 충돌하면 다음 순서로 판단합니다.

1. 현재 작업에 대한 사용자 요구 및 수정 허용 범위
2. 승인된 HARO PRD, 화면 명세, 콘텐츠 및 시안
3. 현재 저장소에서 확인된 구조·기능·디자인 토큰
4. `spec-kit/HARO_SpecKit.md`의 공통 규약과 HARO 레퍼런스 규약
5. `spec-kit/AGENTS.md`의 공통 디자인·개발 규칙 중 위 기준과 양립하는 내용
6. 일반적인 웹 디자인·개발 관행

`spec-kit/AGENTS.md`의 공통 원칙은 HARO의 승인된 명세나 기존 동작과 충돌할 때 무단으로 구조를 바꾸는 근거로 사용하지 않습니다.

기존 사이트를 수정할 때는 기존의 반응형 전략·클래스명·ID·CSS 변수·링크·`data-*` 후크·이벤트 연결을 우선 보존합니다. 접근성·보안 문제나 명세 간 충돌이 있으면 위험과 최소 변경안을 명시합니다.

## 저장소 구조

```text
/
├── README.md
├── index.html                 # HARO 단일 페이지 엔트리
├── pages/
│   ├── notice/                # NOTICE 목록·상세·작성·수정 및 구주소 연결 HTML
│   ├── goods/                 # JSON 기반 공통 상품 상세 템플릿
│   └── cart/                  # localStorage 장바구니
├── css/
│   ├── tokens.css             # 공통 디자인 토큰
│   ├── base.css               # 리셋 및 기본 요소
│   ├── layout.css             # 공통 레이아웃
│   ├── components.css         # 공통 컴포넌트
│   ├── box.css                # HERO 상자 표현
│   └── sections.css           # 페이지 섹션 및 반응형 스타일
├── images/                    # 현재 제공된 이미지·아이콘 자산
├── data/                      # 데이터가 추가될 경우 실제 내용을 확인
├── firebase.json              # Firebase CLI 규칙·색인 파일 경로
├── firebase/
│   ├── firestore.rules        # Firestore 테스트 보안 규칙
│   └── firestore.indexes.json # Firestore 색인 설정
├── js/
│   └── services/              # NOTICE 화면·공통 도구·저장소 및 Firebase 연결
├── document/                  # PRD 및 에이전트 관련 문서
├── task-history/
│   └── task.md                # 이전 작업 요약 및 다음 작업 인계
└── spec-kit/
    ├── AGENTS.md              # 공통 디자인·개발 규칙
    └── HARO_SpecKit.md        # HARO 프로젝트 통합 규약
```

현재 엔트리 파일은 `index.html`이며, CSS는 `tokens.css` → `base.css` → `layout.css` → `components.css` → `box.css` → `sections.css` 순서로 연결되어 있습니다. 현재 저장소에 JavaScript 폴더와 실행 스크립트가 있다고 가정하지 않습니다. 상호작용 구현이 필요하면 PRD와 현재 파일 상태를 확인하고, 기존 요구사항 및 외부 라이브러리 도입 여부를 먼저 검토합니다.

## 구현 원칙

- **범위 보호:** 요청하지 않은 섹션·콘텐츠·파일·기능은 추가, 삭제 또는 전면 재작성하지 않습니다.
- **현재 구조 재사용:** 기존 CSS 분리와 클래스·ID·앵커·접근성 속성·이벤트 후크를 확인 없이 변경하지 않습니다.
- **토큰 우선:** 반복되거나 공통으로 쓰이는 색상·타이포그래피·간격·레이어·모션은 `css/tokens.css`의 변수를 사용합니다. 일회성 장식·일러스트 좌표는 기존 디자인을 보존하고, 공통 토큰으로 바꾸는 것이 적절하지 않으면 이유를 확인합니다.
- **레이아웃 적합성:** 섹션과 콘텐츠의 실제 구조에 맞게 Flexbox 또는 Grid를 사용합니다.
- **접근성과 의미:** 시맨틱 HTML을 사용하고, 이동은 `<a>`, 동작은 `<button>`으로 표현합니다. 키보드 조작, 보이는 포커스, 대체 텍스트, 실제 상태와 동기화된 ARIA를 확인합니다.
- **안전한 변경:** 승인되지 않은 프레임워크·라이브러리·CDN·빌드 도구를 추가하지 않습니다. `!important`나 `overflow-x: hidden`으로 원인을 가리지 않습니다.
- **실제 자료만 사용:** 이미지·폰트·링크·API의 경로와 존재를 확인하고 임시 링크나 임시 문구를 완성된 기능처럼 남기지 않습니다.
