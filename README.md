# HARO 웹사이트 프로젝트

하로 캐릭터와 콘텐츠를 소개하는 단일 페이지 웹사이트 프로젝트입니다. 기본 스택은 HTML5, CSS3, Vanilla JavaScript이며, 현재 저장소의 실제 파일과 승인된 PRD를 기준으로 작업합니다.

## 로컬 미리보기

Node.js가 설치된 환경에서 `preview.cmd`를 실행하거나 프로젝트 폴더에서 `node scripts/preview.cjs`를 실행합니다. 서버 실행 창을 유지한 채 브라우저에서 http://127.0.0.1:8080/ 에 접속합니다. 종료하려면 서버 창에서 Ctrl+C를 누릅니다.

STORY 이미지는 JSON을 불러오므로 `index.html` 파일을 직접 열지 않고 위 HTTP 주소를 사용합니다. 수정 후 브라우저를 새로고침하면 반영됩니다.

## 작업 시작 전 필독

README를 읽고 작업을 시작할 때는 **가장 먼저 [`task-history/task.md`](./task-history/task.md)도 이어서 읽으세요.** 이 파일에는 이전 작업과 미완료 사항이 기록되어 있으므로, 현재 저장소 상태와 대조해 중복 작업을 방지합니다.

1. `task-history/task.md`의 이전 작업, 미완료 사항, 검증 상태를 확인합니다. 현재 요청과 실제 저장소 상태에 맞춰 오래된 인계 내용은 검증·갱신합니다.
2. 이번 요청의 목표, 수정 범위, 보존할 기능과 검증 기준을 확인합니다.
3. [`spec-kit/HARO_SpecKit.md`](./spec-kit/HARO_SpecKit.md)를 프로젝트 공통 규약으로 읽고 적용합니다.
4. [`spec-kit/AGENTS.md`](./spec-kit/AGENTS.md)의 공통 규칙과 현재 작업에 해당하는 부분을 확인합니다.
5. [`document/`](./document/)의 PRD·요약·에이전트 지침 중 현재 작업과 관련된 문서를 확인합니다. 없는 문서나 자산은 추측하지 않습니다.
6. 실제 HTML, 연결된 CSS, 이미지·폰트 경로와 기존 반응형·상호작용 구조를 조사한 뒤 요청 범위만 수정합니다.

작업을 마치면 `task-history/task.md`에 완료한 내용, 수정 파일, 실제 검증 결과, 미완료·미검증 항목을 갱신해 다음 작업이 중복 없이 이어지도록 합니다.

규약이나 필수 자료를 찾을 수 없으면 누락 사항을 밝히고 확인 가능한 범위만 진행합니다. 확인하지 않은 동작이나 검증을 완료한 것처럼 보고하지 않습니다.

## 문서 적용 범위와 우선순위

규칙이 충돌하면 다음 순서로 판단합니다.

1. 현재 작업에 대한 사용자 요구 및 수정 허용 범위
2. 승인된 HARO PRD, 화면 명세, 콘텐츠 및 시안
3. 현재 저장소에서 확인된 구조·기능·디자인 토큰
4. `spec-kit/HARO_SpecKit.md`의 공통 규약과 HARO 레퍼런스 규약
5. `spec-kit/AGENTS.md`의 공통 디자인·개발 규칙 중 위 기준과 양립하는 내용
6. 일반적인 웹 디자인·개발 관행

`spec-kit/AGENTS.md`의 PART 3은 Discovery Expedition 사이트 전용 명세입니다. 해당 사이트를 직접 재현하는 작업이 아니라면 그 사이트의 색상, 타이포그래피, `.outer-box` 레이아웃, 브레이크포인트 및 컴포넌트 수치를 HARO에 적용하지 않습니다. 이 문서의 PART 1·2에 있는 공통 원칙도 HARO의 승인된 명세나 기존 동작과 충돌할 때는 무단으로 구조를 바꾸는 근거로 사용하지 않습니다. `README-1.md` 역시 Discovery Expedition 프로젝트를 위해 작성된 참고 자료이므로, 일반적인 작업 순서와 품질 점검만 참고합니다.

기존 사이트를 수정할 때는 기존의 반응형 전략·클래스명·ID·CSS 변수·링크·`data-*` 후크·이벤트 연결을 우선 보존합니다. 접근성·보안 문제나 명세 간 충돌이 있으면 위험과 최소 변경안을 명시합니다.

## 저장소 구조

```text
/
├── README.md
├── README-1.md                 # Discovery Expedition 참고 문서
├── index.html                 # HARO 단일 페이지 엔트리
├── css/
│   ├── tokens.css             # 공통 디자인 토큰
│   ├── base.css               # 리셋 및 기본 요소
│   ├── layout.css             # 공통 레이아웃
│   ├── components.css         # 공통 컴포넌트
│   ├── box.css                # HERO 상자 표현
│   └── sections.css           # 페이지 섹션 및 반응형 스타일
├── images/                    # 현재 제공된 이미지·아이콘 자산
├── data/                      # 데이터가 추가될 경우 실제 내용을 확인
├── document/                  # PRD 및 에이전트 관련 문서
├── task-history/
│   └── task.md                # 이전 작업 요약 및 다음 작업 인계
└── spec-kit/
    ├── AGENTS.md              # 공통 규칙 + Discovery Expedition 전용 규칙
    └── HARO_SpecKit.md        # HARO 프로젝트 통합 규약
```

현재 엔트리 파일은 `index.html`이며, CSS는 `tokens.css` → `base.css` → `layout.css` → `components.css` → `box.css` → `sections.css` 순서로 연결되어 있습니다. 현재 저장소에 JavaScript 폴더와 실행 스크립트가 있다고 가정하지 않습니다. 상호작용 구현이 필요하면 PRD와 현재 파일 상태를 확인하고, 기존 요구사항 및 외부 라이브러리 도입 여부를 먼저 검토합니다.

## 구현 원칙

- **범위 보호:** 요청하지 않은 섹션·콘텐츠·파일·기능은 추가, 삭제 또는 전면 재작성하지 않습니다.
- **현재 구조 재사용:** 기존 CSS 분리와 클래스·ID·앵커·접근성 속성·이벤트 후크를 확인 없이 변경하지 않습니다.
- **토큰 우선:** 반복되거나 공통으로 쓰이는 색상·타이포그래피·간격·레이어·모션은 `css/tokens.css`의 변수를 사용합니다. 일회성 장식·일러스트 좌표는 기존 디자인을 보존하고, 공통 토큰으로 바꾸는 것이 적절하지 않으면 이유를 확인합니다.
- **레이아웃 적합성:** 섹션과 콘텐츠의 실제 구조에 맞게 Flexbox 또는 Grid를 사용합니다. Discovery Expedition 문서의 박스 계층이나 Grid 제한을 HARO에 일괄 강제하지 않습니다.
- **접근성과 의미:** 시맨틱 HTML을 사용하고, 이동은 `<a>`, 동작은 `<button>`으로 표현합니다. 키보드 조작, 보이는 포커스, 대체 텍스트, 실제 상태와 동기화된 ARIA를 확인합니다.
- **안전한 변경:** 승인되지 않은 프레임워크·라이브러리·CDN·빌드 도구를 추가하지 않습니다. `!important`나 `overflow-x: hidden`으로 원인을 가리지 않습니다.
- **실제 자료만 사용:** 이미지·폰트·링크·API의 경로와 존재를 확인하고 임시 링크나 임시 문구를 완성된 기능처럼 남기지 않습니다.
