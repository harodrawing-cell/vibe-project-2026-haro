# 회원 A 실제 브라우저 테스트 결과

기록일: 2026-11-08. 사용자가 HARO React 실제 브라우저에서 실행하고 전 항목 정상이라고 보고한 결과다. 에이전트가 직접 관찰한 자동 테스트와 구분한다. 정확한 실행 시각·전용 질문 문서 ID는 전달받지 않았으며 추측해 기록하지 않는다.

| 항목 | 판정 | 근거 |
|---|---|---|
| 회원 A 로그인 | 검증 완료·성공 | 사용자 실제 브라우저 실행 보고 |
| 새로고침 후 로그인 유지 | 검증 완료·성공 | 동일 |
| 비공개 Q&A 작성·Firebase 저장 | 검증 완료·성공 | 동일 |
| 작성자 본인의 비공개 질문 열람 | 검증 완료·성공 | 동일 |
| 공개 목록 제목 마스킹 | 검증 완료·성공 | `비공개 질문입니다` 표시 확인 보고 |

사용자가 직접 생성한 이 테스트 질문만 후속 검사 대상으로 사용한다. 정확한 ID는 사용자의 제한된 테스트 대장에 보관하고, 기존 질문과 구분한다. 이번 기록 작업에서 운영 문서·계정·규칙을 변경하거나 삭제하지 않았다.

## 다음 검사 — 결과 대기

1. 별도 브라우저 프로필의 일반회원 B가 로그인한 뒤, A가 생성한 비공개 테스트 질문의 상세 주소를 직접 연다. 제목·본문·답변이 보이지 않고 접근 거절되어야 한다. B와 A의 인증 세션이 다른지 먼저 확인한다. 목록 제목은 마스킹되어야 한다. 필요 시 MEMBER_ADMIN_ACCEPTANCE.md의 읽기 전용 SDK 검사로 qnaDetails/qnaAnswers 모두 permission-denied를 확인한다.
2. 승인 관리자 M의 별도 프로필에서 같은 질문 열람을 확인한다. 합성 답변 저장 후 새로고침하여 답변 유지와 답변완료(status:answered)를 확인한다.
3. M이 본인이 쓴 테스트 답변을 수정하고 새로고침해 반영을 확인한다. A도 수정된 답변을 볼 수 있어야 하고 B는 계속 차단되어야 한다.
4. M의 답변 삭제 기능으로 답변이 비워지고 미답변(status:waiting)으로 돌아오는지 확인한다. 이 동작은 질문 삭제나 qnaAnswers 문서 자체 삭제와 다르다. 테스트 질문은 남겨 둔다.

회원 B 차단과 관리자 M 열람·답변 생성·수정·삭제·상태 변경은 아직 미검증이다. 결과를 받기 전 통과 처리하지 않는다. 신규 가입, A의 질문 수정·삭제, 관리자 정당성 감사 등 이전 미완료 항목도 자동 완료로 간주하지 않는다. GitHub Push·React 배포는 하지 않았다.
