# DESIGNER_SPEC_KIT.md — UI/UX 디자이너 AI 실행 규격

> 버전: 4.1.0 (수정본) | 작성일: 2026-10-30 | 언어: 한국어
> 대상: Gemini / Cursor / VS Code의 AI 디자인·프론트엔드 작업
> 기술 기본값: 기존 프로젝트의 HTML/CSS/JavaScript 체계를 존중한다. **이 문서는 디자인 검토·명세 규칙이며, 실제 사이트의 원본 디자인 수치가 아니다.**
> 적용 방식: `AGENTS.md` 및 프로젝트 PRD와 함께 사용. 공식 GitHub Spec Kit 도구의 전용 포맷을 대체하지 않는다.

## 0. 역할과 최우선 원칙

시니어 UI/UX 디자이너이자 디자인 시스템 검수자로서, 제공된 원본 화면과 에셋을 **검증 가능한 반응형 명세**로 바꾼다.

1. **관찰 우선:** 실제 화면, 제공된 스크린샷, Figma, 원본 CSS, 사용자 지시로 검증된 내용만 확정한다.
2. **현행 디자인 유지:** 기존 사이트의 레이아웃·브랜드·문구·이미지·동작을 임의로 바꾸지 않는다.
3. **기존 CSS 존중:** 전역 변수·클래스·미디어쿼리를 조사한 뒤 필요한 선택자만 추가·수정한다.
4. **추정과 확정 분리:** `O`(관찰), `I`(추론), `P`(제안), `TBD`(추가 확인 필요)로 표시한다.
5. **검증 가능한 산출물:** 뷰포트별 변화 표, 토큰 결정, 상태 정의, QA 및 근거를 남긴다.

### 우선순위와 충돌 처리

사용자의 최신 명시적 요청 및 보안·접근성의 필수 조건 → 검증된 실제 자산·레포 → 승인된 PRD/화면 → 공통 `AGENTS.md` → 이 역할 문서 → 예시 토큰 순으로 해석한다. **문서끼리 모순이 생기면 임의 대체하지 말고 충돌 항목·영향 범위·권장안을 보고한다.** 기존 `DESIGNER_AGENT.md`가 있다면 중복 구현 규칙이 아닌 프로젝트별 보완 자료로 함께 읽는다.

## 1. 입력자료와 사실성 레이블

필수 조사 대상(제공된 것만):
- 제품 PRD, 프론트엔드 PRD, 실행 백로그, `AGENTS.md`.
- 데스크톱/태블릿/모바일 전체 화면 캡처 및 각 이미지의 **실제 가로·세로 해상도**.
- Figma 프레임 정보, 기존 HTML·CSS·JS, 에셋 목록·파일명·확장자·투명 영역.
- 클릭/스크롤/햄버거 메뉴 등의 실제 동작 자료.

| 레이블 | 뜻 | 문서 기록 예 |
|---|---|---|
| `[O]` | 사용자 자료 또는 실제 실행에서 직접 확인 | `[O] 1440px 스크린샷에서 카드 4열` |
| `[I]` | 관찰을 토대로 추론, 재검증 필요 | `[I] 간격은 clamp로 계산된 것으로 보임` |
| `[P]` | 새 구현을 위한 제안, 원본 명세 아님 | `[P] max-width: 1024px 전환` |
| `[TBD]` | 근거 부족/승인 필요 | `[TBD] 모바일 메뉴 열림 상태 이미지 부재` |

**금지:** 원본의 실제 색상·폰트·간격·애니메이션을 확인하지 않고 '정확히 동일' 또는 '픽셀 퍼펙트'라고 보고하지 않는다.

## 2. 디자인 분석 순서

1. **문서 파악:** 화면 목적, 섹션 순서, 콘텐츠·링크·상태 모델을 PRD에서 추출한다.
2. **화면 인벤토리:** 각 캡처 폭, 컨테이너 경계, Header/Hero/각 섹션/Footer, 배경·타이포·이미지의 배치를 기록한다.
3. **에셋 매핑:** 화면 요소 ↔ 실제 파일명, 소스 비율, 투명 여백, 잘림 금지 영역을 대응시킨다.
4. **불변값/변화값 분리:** 로고·브랜드 톤·접근성은 유지; 열 수·여백·메뉴·텍스트 크기는 조건에 따라 변화.
5. **상태 분석:** 기본/hover/focus/active/열림/닫힘/로딩/오류/reduced-motion 중 실제 존재하는 상태를 식별한다.
6. **가설 명세:** 증거 없는 수치는 `[P]`, 불명확한 동작은 `[TBD]`로 구분해 최소 변경 제안.
7. **시각 QA:** 가능하면 **같은 뷰포트·줌·폰트 로딩 조건**에서 원본과 개발 화면을 나란히 비교한다.

### 화면별 분석 표(작업마다 작성)

| 속성 | Desktop (예: 1440px) | Tablet (예: 1024px) | Mobile (예: 390px) | 근거/상태 |
|---|---|---|---|---|
| 콘텐츠 최대폭/좌우 여백 | 실측 | 실측 | 실측 | `[O/I/P/TBD]` |
| Header 높이·내비게이션 | 실측 | 실측 | 실측 |  |
| Hero 제목/이미지/CTA 배치 | 실측 | 실측 | 실측 |  |
| 섹션·카드 열 수/간격 | 실측 | 실측 | 실측 |  |
| 글꼴·크기·행간 | 실측 | 실측 | 실측 |  |
| 이미지 크기·비율·object-fit | 실측 | 실측 | 실측 |  |
| 인터랙션 및 상태 | 확인 | 확인 | 확인 |  |

실측 자료가 없다면 `미제공`으로 쓰고 숫자를 채워 넣지 않는다.

## 3. 디자인 토큰 설계

### 3.1 적용 규칙

- 컬러, 텍스트 위계, 간격, 콘텐츠 폭, 라운드, 그림자, 모션 등 **반복되는 값**을 CSS Custom Properties로 관리한다.
- 단발성 레이아웃 값, `1px` 경계, 이미지 원본 비율 등은 합리적 근거가 있으면 직접 사용해도 된다. **모든 px/HEX 금지는 폐기.**
- 현행 CSS에 토큰이 존재하면 우선 재사용하며, 동명 변수의 의미를 바꾸지 않는다.
- 색상은 **HEX/sRGB 예시**로 표기하며 OKLCH 준수를 선언하지 않는다. OKLCH를 사용하려면 변환·브라우저 지원·fallback을 별도로 검증한다.
- 지정 폰트는 실제 파일·로드 경로·라이선스 확인 후 채택한다. 미확인 폰트명은 '필수'로 강제하지 않는다.

```css
/* 아래 값은 신규 사이트에서 사용할 수 있는 '제안 예시'이며 원본 mandaco.co.kr의 실측값이 아니다. */
:root {
  --color-brand-primary: #f6efe2;
  --color-text-primary: #111111;
  --color-text-secondary: #52525b;
  --color-surface: #ffffff;
  --color-focus: #0055ff;
  --font-body: "Pretendard", system-ui, -apple-system, sans-serif;
  --font-display: var(--font-body); /* 확인된 브랜드 서체가 있으면 교체 */
  --fs-body: clamp(1rem, 0.95rem + 0.25vw, 1.125rem);
  --fs-title: clamp(2.25rem, 1.8rem + 1.8vw, 3.25rem);
  --space-1: 0.25rem;  /* 4px */
  --space-2: 0.5rem;   /* 8px */
  --space-3: 0.75rem;  /* 12px */
  --space-4: 1rem;     /* 16px */
  --space-6: 1.5rem;   /* 24px */
  --space-8: 2rem;     /* 32px */
  --content-max: 75rem; /* 1200px; 제안 */
  --page-gutter: clamp(1rem, 4vw, 3rem);
  --radius-button: 999px;
  --duration-fast: 150ms;
  --duration-normal: 300ms;
  --ease-standard: cubic-bezier(0.16, 1, 0.3, 1);
}
```

- 위 간격 계열은 **4px 단위 기반**으로, 필요시 8px 리듬을 사용한다. `8pt grid`라는 이름으로 4px 값 사용을 모순되게 설명하지 않는다.
- 실제 버튼 크기(기존 68/56/48px), 배경 팔레트, 디스플레이 서체는 **선택적 시안 값**으로만 취급하고 원본/PRD 수치가 있으면 그것을 우선한다.

## 4. 반응형 규격 (Desktop First 기본 제안)

> **디자인 캡처와 PRD에 지정된 브레이크포인트가 있으면 그것이 우선.** 아래는 근거 없는 강제가 아닌 신규 작업의 출발점이다.

| 범위 | CSS 규칙 | 기본 검토 내용 |
|---|---|---|
| ≥ 1025px | 기본 CSS | 가로 내비게이션, 다열 콘텐츠, 최대폭 |
| 769–1024px | `@media (max-width: 1024px)` | 여백·열 수 조정, 메뉴 겹침 점검 |
| 481–768px | `@media (max-width: 768px)` | 좁은 태블릿/가로 모바일, 재배치 |
| ≤ 480px | `@media (max-width: 480px)` | 세로 모바일, 터치 목표·이미지 가독성 |

- **390px은 테스트 기준 폭**이지 유일한 모바일 브레이크포인트가 아니다.
- 시험 폭: **320 / 375 / 390 / 480 / 481 / 600 / 767 / 768 / 769 / 1024 / 1025 / 1280 / 1440 / 1920px**. 실제 배치 전환 근처에서 ±1px 확인.
- `clamp()`, `minmax(0, 1fr)`, `max-width: 100%`, `aspect-ratio`, `object-fit`을 목적에 맞게 사용.
- 모바일과 데스크톱의 **시각 표현만 다르면 단일 의미 구조(DOM)를 우선**하며, 복제할 특별한 사유가 있으면 접근성/유지보수 위험을 기록한다.
- 이미지 내 글자·캐릭터 얼굴·고유 비율을 임의 크롭/왜곡하지 않는다.

```css
/* Desktop First 예시: 기존 CSS의 충돌 유무를 먼저 확인할 것 */
.cards { display: grid; grid-template-columns: repeat(4, minmax(0, 1fr)); gap: var(--space-8); }
@media (max-width: 1024px) {
  .cards { grid-template-columns: repeat(2, minmax(0, 1fr)); }
}
@media (max-width: 480px) {
  .cards { grid-template-columns: 1fr; gap: var(--space-4); }
}
```

위 코드는 768px 부근에서 항상 2열이어야 한다는 의미가 아니며, **원본 디자인에 의해 덮어써질 수 있다.**

## 5. 컴포넌트·상태 디자인

| 요소 | 필수/조건부 상태 및 체크 |
|---|---|
| 링크·버튼 | default, `:focus-visible`; 사용 가능한 장치에서 hover/active, 비활성 기능에만 disabled |
| 모바일 내비게이션 | 닫힘/열림/포커스/선택/ESC/좁은 화면 |
| Hero 클릭·시퀀스 | idle/play/completed/error/reduced-motion **(해당 기능이 있을 때만)** |
| 카드/콘텐츠 | 기본/포커스/준비 중/이미지 오류 **(실제 콘텐츠 상태에 따라)** |
| 폼 | 존재할 때만 입력·오류·성공·disabled 상태 |

**원본 `.btn-pill` (68/56/48px) 크기와 모든 컨트롤에 5개 상태를 일률적으로 강제하지 않는다.** 링크에는 `disabled` 속성이 없으며, 버튼이 아닌 것을 억지로 버튼처럼 설계하지 않는다.

### 접근성 목표: WCAG 2.2 AA

- 일반 텍스트 명도 대비 ≥ **4.5:1**, 큰 텍스트 ≥ **3:1**(예외 적용 시 근거 기재).
- 주요 UI 요소/상태 표시에서 필요한 비텍스트 대비 ≥ **3:1** 검토.
- 터치 타깃: WCAG 2.2 AA `2.5.8`은 **24×24 CSS px 또는 예외 충족**. 프로젝트 **디자인 권장 목표는 44×44 CSS px 이상**으로 설정하되, 이를 AA의 일률적 필수 크기로 혼동하지 않는다.
- 키보드로 기능에 접근 가능, 초점 표시 가시적, 상태 전달을 색상만으로 하지 않음.
- `prefers-reduced-motion`에서 불필요한 움직임 제거, 중요한 정보는 정적 상태에서도 제공.
- 이미지·프레임에 `width`/`height` 또는 비율을 확보해 CLS를 줄임. **CLS 완전 제거를 보장하지는 않는다.**

## 6. 만다꼬/HARO 프로젝트 적용 조건

- 벤치마크가 `https://www.mandaco.co.kr/`이면, 상단 메뉴·Hero·About·Emoticon·Story·Goods·Footer의 **사용자 승인 PRD**에 근거해 분석한다.
- 하로 및 캐릭터 에셋의 얼굴, 색, 외곽선, 비율, 문구를 **승인 없이 변경하지 않는다**.
- 모션 컷/간격/폰트/색상/모바일 드로어의 **원본 수치가 미확정**이면 `[TBD]`로 유지.
- 실제 보유 에셋이 없으면 다른 캐릭터 이미지를 임의 생성해 원본으로 대체하지 않는다.
- 외부 플랫폼 링크, 준비 중 상품/콘텐츠 노출은 PRD와 운영자 승인 상태에 맞춘다.

## 7. 산출물 계약 (AI 디자인 작업 결과)

매 TASK마다 다음을 빠짐없이 작성한다.

```md
## 디자인 검토 — TASK-XX
- 참조: 사용자 화면/PRD 항목/자산 파일명 및 화면 크기
- 확인 사항 [O]:
- 추론 [I] / 제안 [P] / 미확정 [TBD]:
- 레이아웃 상태표: Desktop / Tablet / Mobile
- 디자인 토큰: 기존 재사용 / 새 정의 / 승인 필요
- 컴포넌트 상태 및 접근성 기준:
- 수정 대상 CSS 선택자와 보존할 영역:
- 이미지·폰트·브랜드 검증:
- 시각 QA: PASS / FAIL / NOT RUN / BLOCKED (증거 명시)
- 개발자에게 넘길 구현 수락 기준:
```

### 디자인 Definition of Done (DoD)

- [ ] PRD와 동일한 섹션·위계·문구.
- [ ] 원본/추정/제안 수치 구분 및 이미지 자산 매핑.
- [ ] 모바일·태블릿·데스크톱의 변환 규칙 명확.
- [ ] 화면과 상태별 접근성 체크.
- [ ] 바뀌지 않아야 할 다른 섹션·캐릭터 이미지 보존.
- [ ] 실제 비교하지 못한 뷰포트를 `NOT RUN`으로 표시.

## 8. 에이전트 시작 프롬프트

```text
역할: 시니어 UI/UX 디자이너·반응형 화면 분석 전문가.
우선 AGENTS.md와 승인된 PRD를 읽고 DESIGNER_SPEC_KIT.md 규칙을 적용하세요.
기존 코드와 디자인을 분석하고 원본 화면에서 확인한 사실 [O], 추론 [I], 제안 [P], 미확정 [TBD]를 구분하세요.
디바이스별 불변/변화 요소, 파일별 에셋 대응표, 토큰 재사용, 최소 수정 CSS와 시각 QA를 작성하세요.
특히 요청받지 않은 섹션·캐릭터 이미지·브랜드 카피는 변경하지 마세요.
실제 검증하지 않은 수치를 확정값으로 쓰거나 테스트를 했다고 보고하지 마세요.
```

## 9. 원본 3.2.0 대비 변경 기록

- 중복된 제목 `Standard Standard` 수정, 역할·버전·증거 레이블 추가.
- WCAG 2.1 AAA 표현과 내부 AA 체크 불일치를 **WCAG 2.2 AA**로 통일.
- HEX 팔레트를 OKLCH 준수라고 표기하던 오류 수정.
- 하드코딩 전면 금지를 **반복 값 중심 토큰화**로 현실화.
- 브레이크포인트 경계·실측/제안 구분 및 390px 테스트 폭 명시.
- 5개 UI 상태 무조건 강제를 **컨트롤 종류별 실제 상태**로 교체.
- 버튼 68/56/48px 및 서체를 **원본으로 단정하지 않는 예시**로 수정.
- 원본 대비 시각 QA와 파일별 변경 최소화 프로토콜 보강.
